# 04 — Feature case studies traced through commits and tests

Nine pieces of work in storytold/photocraft ("PhotoCraft"), each traced from where the requirement
came from to how it reached `main` and what happened next. The question for each is **how the work was
verified**. Showing that commits exist is not enough.

Pinned upstream: `main` = `74330157cb` (2026-11-12). Primary inputs: E09 (case traces), plus E04, E05
and E07 where they touch these cases. `deliverables/01c-errata.md` overrides the evidence files. Facts
added during this synthesis are listed at the end. Times are given as git records them (`a:` author
date, `c:` committer date). Elapsed times are computed in UTC.

**Labels.** VERIFIED = seen in a cited primary source. INFERRED = reasoned from verified facts, with the
chain stated. PROPOSED = our recommendation. "WF" = a GitHub page read through a WebFetch summary. WF
evidence is lower fidelity: a small model summarised the page, so quotes are short.

**Attribution rule.** The trace tables give AI involvement exactly as written in trailers, author
fields or branch names. A commit with no trailer is "none recorded". That means attribution is
unknown, not that a human wrote it.

### Terms used throughout
- **One-shot**: the root commit 16941f7198 (2026-09-30), which has 241 files and +42,241 lines. The
  repository started from it (E01).
- **Squash / rebase-merge**: a squash is a single-parent main commit with committer `GitHub` and the PR
  number in its subject. A rebase-merge is a single-parent main commit whose committer is the merging
  maintainer.
- **Oracle**: an independent reference output that the implementation is compared against.
- **Floor**: a minimum pass count asserted by a test, which may only be raised (a "ratchet").
- **Scorecard**: `docs/scorecard.md`, generated by `cargo xtask scorecard`. CI checks that it is not
  stale (E04-050).
- **panic_hunt**: `crates/engine/tests/panic_hunt.rs`, a test that calls every registered engine
  command with adversarial parameters (E04-012).
- **Integration batch**: a branch on which a maintainer or agent merges many community PRs and repairs
  them before landing on main (E07-002).
- **CodeRabbit**: a third-party AI review bot that comments on PRs (E05-030).
- **Merge skew**: two PRs that each pass CI against their own base but break main once both land
  (E07-003).

## Case A — MCP server and control protocol

### 1. What it is and why it was chosen
PhotoCraft has two automation surfaces. The JSON control protocol drives the running app. The MCP
server (Model Context Protocol, built on the `rmcp` crate) lets external agents edit documents. This
case was chosen because it is the oldest feature with tests from day 0. Its specification also moved
through three sources: an in-repo doc, a sibling project's issue, and user bug reports.

### 2. Trigger and specification
- **VERIFIED.** The specification was a doc inside the one-shot root commit:
  > "Each request is one JSON line" … "An MCP server will wrap this same protocol (milestone M11)."
  (16941f7198:docs/control-protocol.md:3,16; E09-A-001). It is a list of 14 methods and an
  engine-command table (E04-013). There is no separate requirements document.
- **VERIFIED.** The day-1 architecture plan already set the shape: "Stdio for agent CLIs, and
  optionally loopback TCP with a token so it can attach to a running GUI" (16941f7198:docs/architecture.md:426;
  E04-017). Its acceptance milestone was "an agent edits a PSD through MCP" (16941f7198:docs/architecture.md:523).
- **VERIFIED.** On 10-09 the spec source moved to a sibling project. 15e35cf605 says: "The MCP server
  follows the crafts' shared conventions (FilmCraft #28)". After that it moved to user reports: #415
  and #503–#506/#529 are cited in the subjects of 55054b5fcc and 7eb3b2e072.

### 4. Verification actually used
- **VERIFIED. In-process client tests from day 0.** The MCP server runs inside the test process and a
  real MCP client calls its tools: "Spin the MCP server in-process (tokio duplex), call tools as a
  client." (ae92ac20bf:crates/automation/tests/mcp.rs:1). Bridge mode is tested "against a fake control
  server" (:295–297), not against the real GUI (E09-A-002).
- **VERIFIED. A wire-level test arrived with the shared conventions.** mcp_wire.rs says: "Exercise the
  actual line transport, including recovery and modern result fields." (15e35cf605:crates/automation/tests/mcp_wire.rs:1).
  The conventions specify error codes (−32602 strict keys, −32700 malformed line), and those codes
  became the assertions.
- **VERIFIED. Scripted agent acceptance tests.** `agent_tasks.rs` completes "10 scripted edit tasks
  over MCP … and checks the outcome through `doc_inspect` … never engine internals" (E04-026,
  added 536a7346fb). They run in the CI gate.
- **VERIFIED. Bug-fix commit bodies state the failure mechanism and the test count.** For example,
  8a2f31c2c4: "after any command panicked … every later tool call … failed for the rest of the MCP
  session, losing unsaved work … 1 test (automation server)."
- **Not verified (VERIFIED absence):** E09-A-002 found no golden JSON-RPC transcripts. Bridge mode
  is never tested end-to-end against the GUI in CI. No commit shows a developer agent checking its own
  work over MCP (E04 table row "MCP server").

### 5. Review and integration path
- **VERIFIED.** The genesis work went straight to main as bulk commits with no PR. From 10-03 the work
  came through PRs: squashes by BFlat (#439, #546, #548) and storybored379 (#1668), and a rebase-merge
  of community PR #1533 by BFlat.
- **VERIFIED.** #1533 took 2 h 31 min from first commit to main (01:41Z → 04:12Z on 10-09). A
  Claude-authored lint fix was cherry-picked into it from `claude/integ-batch-7` and landed in the same
  push (cff8daf185 committer time equals 0e0311d245's).
- INFERRED: the integration-batch agent ran clippy on a newer toolchain (1.99), found the lint, and
  the maintainer carried the fix into the community branch so the PR would merge green (E09-A-004).
- Unknown: the PR pages for #1533 and #1668 were not fetched, so human review of them is unrecorded.

### 6. Aftermath
- **VERIFIED.** `git log origin/main -- crates/automation` gives 431 commits and `-i --grep=mcp` gives
  135 (E09-A-003). `docs/control-protocol.md` grew from 50 to 840 lines, adding HMAC auth, jobs, the
  bridge and the headless server (E04-013). It is also among the files with the most fix commits:
  32 (E07-025).
- **VERIFIED.** Flakiness: the MCP `photocraft://commands` test "failed 9/30" beside the rest of
  mcp.rs, because parallel tests filled and cleared the process-wide render caches; 18c5420039
  (2026-10-11, `Co-Authored-By: Claude Opus 5.5`) moved it to its own test binary,
  `tests/mcp_resources.rs`. The same commit's font-generation and frame-window fixes were for other
  tests (E07 §3 table).

### 7. What this case demonstrates about method
- (a) **VERIFIED.** The tests drive the feature through its public interface: a real MCP client, a
  raw JSON line transport, and `doc_inspect` for outcomes. Engine internals are not used. This made
  user-report fixes cheap, and each one added a named test (8a2f31c2c4, 7eb3b2e072, 7ba589e01c).
- (a) **VERIFIED.** Adopting a shared convention (FilmCraft #28) turned the error codes and the
  strict-key behaviour into assertions within one PR (#1668).
- (b) **VERIFIED.** The bridge to the live app is checked only against a fake server. Users found
  batch `wait`, bad-line and job-visibility bugs within a week (#415, #503–#514).
- (b) **INFERRED.** A toolchain lint drift (clippy 1.99) was caught by an agent integration branch,
  not by the PR's own CI. That chain is visible only because the cherry-pick note was kept (cff8daf185).
- (c) **INFERRED.** Transferable pattern: write the protocol doc first, test through an in-process
  client, then add a wire test once error semantics are fixed. Precondition: the server can run
  in-process with a headless core (E04-008).

## Case B — Community bug #1381 fixed on a `claude/fix-*` branch

A user reported that selecting text on Wayland deleted it. On 10-08 an agent session fixed it,
together with three sibling issues, each on its own `claude/fix-<issue>-<slug>` branch. The case was

### 7. What this case demonstrates about method
- (a) **VERIFIED.** Each fix is small, comes with its own test, and has a fixed message shape (subject
  `Fix #N: <user-visible outcome>`, then symptom, cause, behaviour). The code comment cites the issue
  (0582884a5f:crates/ui-egui/src/type_tool.rs). Together with the `Claude-Session` link, this gives traceability from
  issue to session to commit to test.
- (a) **VERIFIED.** The test pins both sides: the bug must not recur, and real composition must still
  work. This guards against "fix by disabling the feature".
- (b) **VERIFIED (WF).** No human review, and only 4 of 7 checks were reported passed at merge (skipped
  path-selected jobs may be counted as not passed; errata #14). Correctness
  rested on the agent's test and the maintainer's judgement.
- (b) **INFERRED.** The diagnosis came from the same agent that wrote the fix. No independent repro
  on Wayland is recorded, so the test encodes the agent's own model of the bug.
- (c) **INFERRED.** Transferable pattern: one issue, one agent branch, one regression test, with a
  session link in a trailer. Precondition: the UI can be driven headlessly with synthetic input
  events (egui_kittest here; E04-028).

## Case C — The "never crash" campaign (2026-10-04)

### 1. What it is and why it was chosen
On day 5, one maintainer turned a rule into a mechanical guard and swept the whole workspace in one
afternoon. The sweep used 12 single-commit branches, one per crate area, and each carried an AI
co-author trailer. The case was chosen because it is the cleanest example in the history of the
sequence rule, fuzzer, lint, sweep, runtime net.

### 2. Trigger and specification
- **VERIFIED.** Inputs came the day before. Users reported crashes, e.g. issue #7 (10-03, "Dies as
  soon as i open jpeg image to edit", WF). Community PRs #16/#17 fixed panics (8a2f31c2c4,
  b6a95b6c8d). See E07-009. INFERRED: the causal link is by timing only; no commit states it.
- **VERIFIED. The specification was written down before the code, in three steps on 10-04:**
  1. 00:10 −0400, ed0b99964d: "AGENTS.md: add rule 9 — never panic on input (commands return Err)".
  2. 00:24, bf111b524e: a harness that operationalises rule 9, plus the first fixes it found.
  3. 11:14, 50a27e6c74 (#33): the full section at the top of AGENTS.md's golden rules.
     > "Don't ship a feature by adding a panic path; fix a crash before building on top of it." …
     > "**Prove it.** Every crash fix comes with a small synthetic regression test that panicked before the fix." …
     > "**Enforced by clippy.** … Clean crates carry `#![deny(clippy::unwrap_used, …)]`; new crates start with it."
     (50a27e6c74:AGENTS.md diff; still at 74330157cb:AGENTS.md:103.) The body names an external
     source: "Standard: craftrules/standards/never-crash.md". That file is not in this repository, and
     `craftrules` was later declared retired (`AGENTS.md:18`; E05 lead).

## Patterns across cases (each recurs in ≥3 cases)

1. **The test lands in the same change as the code, and is named for the behaviour.** A
   (8a2f31c2c4, 7eb3b2e072), B (all four), C (bf111b524e, 69f0e25d5f), D (corpus_regressions.rs), E,
   F, H. VERIFIED. **But it is not universal**: C #54 (and #58's engine guard), G 16 of 27, and the backfill campaign
   "eight fixes merged without one" (E07-015). The norm is a convention enforced by no gate.
2. **External or differential oracles, where they exist, are the strongest verification in the
   record.** D (Photoshop composites, 2/255), F (bit-exact against a base worktree), C (registry
   fuzzer), A (wire-level error codes from a shared convention). VERIFIED. Cases without one (B, G, H)
   rely on the author's own model of the bug, and in H that model was wrong (E09-H-001).
3. **Verification gaps get declared rather than closed.** E ("Native/browser acceptance … remain
   open"), F ("What this does not fix", pre-existing failures), D (write oracle "does not prove that
   Photoshop can open the output", 499 extracted tests), C (opt-in fuzz). VERIFIED. This honesty is
   valuable only if someone tracks the open gates. Nothing in the repository does (INFERRED, from
   E05-071: the panic_hunt gap stayed open 13 days).
4. **Human review is uneven. AI review is near-universal but advisory.** No human review: B, D
   #13414, G #8417. Substantive human review: E, F, H. CodeRabbit found real defects in E
   (accessible names), F (timing harness) and H (2+2 comments), and was merged over in G #8452.
   VERIFIED (WF), matching E05-030 and E05-035.
5. **Post-merge discovery is the main source of follow-ups.** A (user reports within a week), E (RTL
   after 3.8 days), H (tester within hours), I (main broken 13 h). VERIFIED. Each follow-up became a
   named test or a named incident, which is the project's main learning loop.
6. **Agent attribution is visible at the commit level, but uneven.** Explicit trailers and session
   links: A, B, C, H. Only a branch prefix or third-party tool: E (`codex/`, Codebuff), I (Cursor).
   None recorded: F, G and D's 10-05 and 11-12 commits (D's Timothy Daly squashes carry Claude

7. **Decomposition into one-issue or one-area PRs is the default shape.** B (1 issue = 1 branch), C (1
   crate area = 1 branch), G (1 finding = 1 PR), A (report batches). VERIFIED. It made changes
