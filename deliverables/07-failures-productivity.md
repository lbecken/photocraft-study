# 07 — Failure and productivity analysis

Scope: how PhotoCraft (`storytold/photocraft`) failed, how fast failures turned into rules or gates, and
what its output and rework numbers can and cannot tell a reader who wants to copy the method. Upstream
pinned at `main` = `74330157cb` (2026-11-12). The history spans 44 UTC days, from 2026-09-30 to 2026-11-12.
ISO weeks run Monday to Sunday: W40 starts 2026-09-28, and W46 is partial (Mon to Thu).

Primary inputs are E07 (failures), E03 with `data/E03_*.csv` (quantities), E08 (developer statements),
E05 §1/§5/§7, E09 (case traces), E01 (genesis and parity), E02 (rules) and E06 (workflow). Every claim
carries an evidence ID and the underlying sha, path, PR or URL.

Labels: **VERIFIED** means seen in a primary source. **INFERRED** means reasoned from verified facts,
with the chain given. **PROPOSED** means our recommendation and not a PhotoCraft practice. A commit
without an AI trailer is "attribution unknown", not "human". Where a commit carries a trailer, this file
says "AI-attributed commit". It never says "the AI caused".

### Terms used below
- **Red main**: `main`'s CI is failing after a merge. "Fix main" commits repair it.
- **Semantic merge skew**: two PRs that are each green against their own base, but whose union fails
  (compile error, duplicate symbol, failing test). Without a merge queue, GitHub tests each PR alone.
- **Integration batch**: a maintainer branch that merges many community PRs, repairs them and lands as
  one merge commit. Examples are `davidmann4/integration-batch-7..20` (10-23 → 11-06) and
  `claude/integ-batch-1..11` (10-08/09, CI-only) (E07-002, E06-021/022).
- **Manual merge queue**: commits labelled "(merge queue)", in which main is merged into a PR and the
  gates are re-run before merging (e.g. fda05f7b02, 11-08).
- **Scorecard**: `docs/scorecard.md`, generated by `cargo xtask scorecard` and checked fresh in CI.
  Among other things it counts "Settings that do nothing" (E01-018, E07-014).
- **House rules**: the 15 org-wide rules copied into `AGENTS.md:1-20` from `storytold/craft-contrib`
  on 2026-11-06 (7d8648dfcb). Rule 15 is "No agent attribution" (E02-011).
- **panic_hunt**: a fuzz test that dispatches every command with hostile parameters
  (`crates/engine/tests/panic_hunt.rs`, added bf111b524e).
- **Mechanical** correction: a CI step, lint, test or compile-time check that fails without human
  judgement. **Advisory** correction: prose in AGENTS.md or docs, a label, or a review norm.

### F1 — Individually-green PRs collide on main (semantic merge skew)
- **Definition.** Two PRs pass CI on their own bases. Their union fails on main.
- **Incidents (VERIFIED, E07 §2).**
  - 6103da5278 (#798, 10-07): "Format red on main since #663 + #700".
  - 351149f0df (#6906, 10-17): "#5344 added the export_presets field … #5616 … lacked the new field,
    so main stopped compiling (E0063)". TTF 13 h 12 m.
  - 06650357d8 (#13128, 11-11): "#9781 and #10983 each defined TAG_JPEG_TABLES and TAG_PREDICTOR …
    merged minutes apart, so main stopped compiling (E0428)".
  - df055f3dcb (#5941, 10-15): "#5614 renamed the built-in profile … after #5208 hard-coded '(Photocraft)'".
- **Detection.** CI runs on main. Before 10-07 these were mostly cancelled (F3).
- **Correction.**
  - Integration batches from 10-18 (E07-002). Commits naming red main: W41 16, W42 4, W43–W45 0,
    W46 11 (E07-005). The W43–W45 zeros coincide with the batches. That is a correlation, not a
    demonstrated cause (INFERRED).
  - The manual "(merge queue)" practice from 11-08 (fda05f7b02). The grep `--grep='(merge queue)'` on
    main finds 7 commits on 11-08 to 11-11; E07-003's 9 counts all refs (errata #2).
  - No GitHub merge queue (`merge_group` absent, E07-003). **Process, not mechanical.**
- **Agent link.** AGENTS.md §6, present since 10-01, already anticipates in-tree collisions between
  parallel agents: "If someone else's in-progress edit breaks the build, wait and retry; don't fix
  their files." (`74330157cb:AGENTS.md:174`, E02-003).

### F2 — Duplicate or conflicting work from parallel contributors and agents
- **Definition.** Two contributors or agents do the same work, or add the same row, constant or
  table. Detection then happens at merge or build time, or not at all.
- **Incidents (VERIFIED).**
  - 25f211500b (#834, 10-07): "Both PRs added Korean labels … ko.tsv listed each twice". The fixing
    commit is AI-attributed (Opus 5.5).
  - 29e4039c72 (#9009, 10-23): "Two PRs that landed together each added [people.ronibalthazar]".
  - 06650357d8: duplicate TIFF constants (E0428).
  - 252a47ef76 (10-11): "i18n(cs): drop rows #3039 and #3454 both added".
  - At PR level: closed-unmerged duplicate fixes #11854, #11846 and #11713 (E06-015, WebFetch). The
    Levels revert 70cb31610b was superseded by #3871.
- **Detection.** Compiler (E0428), catalog consistency tests (E07 §9 F2), maintainers, and the
  ticket-craft GitHub App, which labels issues `duplicate` (E06-033).
- **Correction.** House rules 2 "Check, then claim" and 6 "Look for a better pull request"
  (`AGENTS.md:7,11`, 11-06). Both are advisory. Issue epics with "Free to pick up / Being worked on"
  tables act as claim boards (#13458, E06-034).
- **Developer link (VERIFIED, P1).** RFC-0006 lists as observed agent failure modes "duplicate PRs,
  fixes for bugs already fixed on `main`, PRs left as drafts, or code that uses functions that don't
  exist" (https://github.com/storytold/craft-contrib/blob/main/rfcs/0006-coding-agents.md, via WebFetch,
  E08-028). The house rules are the stated answer.

### F3 — CI blind spots created by cost-cutting
- **Definition.** Saving runner time or slots removes coverage, so breakage surfaces later or in a
  different place.
- **Incidents (VERIFIED).**
  - "Between 09:56 and 20:34 UTC on 2026-10-07, 80 of 83 push runs on main were cancelled, and a
    formatting break from two PRs that were each green alone (#663 + #700) went unnoticed" (07174271d5,
    #800, Tanish Manku, AI-attributed commit, E07-004).
  - The same change made PRs Linux-only unless platform paths change or `full-ci` is set. Later
    Windows-only reds: ee3ebfa748 (#2042, "Windows CI red since #1882"), 184c226a76 (#4147) and
    79a33dae9c (#13199, the PR ran Linux only).
  - macOS removed from PR/main CI on 10-09 because "5 macOS slots in total" (bb3108cfd2). macOS is
    tested only by `release.yml` (`ci.yml:74-75`, E05-006).
  - Sonar is skipped on fork PRs (E05-029).
  - nextest's process isolation hid a race that `cargo test` on FreeBSD exposed (7091cb6b8c, E07-008).
- **Correction.**
  - Main runs never cancelled (`74330157cb:.github/workflows/ci.yml:66-68`), mechanical, the same day.
  - `full-ci` label, opt-in and advisory.
  - Day-rotating test sweeps cap cost while covering every case within N days (E05-021).
  - Cost trade-offs are documented inline in runner-minutes (E05-005).
  - The macOS gap remains.

### F9 — Gate additions that themselves break main

- **Incidents (VERIFIED).**

## B.8 What public data cannot measure, and how a project could instrument it

**Not measurable from the public record (VERIFIED absence, E08 §6, E02 §6):**
1. **Token or dollar cost.** No figure anywhere. Cost is distributed to contributors by design
   (E08-018). RFC-0006 lists "spending money" only as a stop-and-ask item.
2. **Human supervision hours.** Who reviewed, for how long, and who pressed merge on 2,690 squash
   merges are not in git (E03 §4).
3. **Prompts, specs and briefs.** `plan/` and `log/devlog.md` are gitignored. `Model-Effort:` names a
   "briefed" role on 25 non-merge commits by one contributor, but no brief is published.
4. **Abandoned agent sessions.** Session ids exist only on landed or pushed commits. Sessions that
   produced nothing leave no trace. The 2,238 unmerged heads cannot be attributed.
5. **Concurrency over time.** No per-agent identity or session coverage exists. Bursts by one identity
   are ambiguous between parallel sessions and batch rebases (E03-014).
6. **Breaking-PR attribution.** It is possible in principle from git, but not tabulated in the
   evidence (a gap).
7. **Defect escape rate.** Issue states and labels are blocked from the API. Only WebFetch samples
   exist.

**PROPOSED instrumentation** (our recommendation; none of it is PhotoCraft practice):

| Gap | Instrument | Cheapest implementation |
|---|---|---|
| Cost | Per-session token and $ ledger keyed by session id | Agent wrapper appends `{session, model, tokens_in/out, usd, wall_s}` to a log; CI posts a per-PR sum as a check summary |
| Provenance | Mandatory structured trailers on *every* commit: `Agent-Session:`, `Agent-Model:`, `Agent-Role:` (driver / briefer / writer, generalising `Model-Effort:`) | `commit-msg` hook plus a CI check that rejects missing trailers; keep PR-text attribution optional if rule 15 is wanted |
| Supervision | Required approving review recorded with a "minutes spent" field, or a review-start/approve timestamp pair | Branch protection with required reviews; a bot computes first-review latency and approval coverage weekly |
| Specs | Commit the brief: `briefs/<session>.md` (or attach it to the PR) for every agent-written PR | PR template field linking the brief; CI warns when absent |
| Abandoned work | Session registry: start, end, outcome (`landed` / `abandoned` / `superseded`) | The wrapper writes on exit; a weekly report joins it with PR state |
| Merge skew | Count "union failures" caught by a merge queue against failures on main | Enable `merge_group`; label each fix-main PR with the breaking PR pair |
| Concurrency | Sessions active per hour from the registry | — |
| Quality | Escape rate = user-reported regressions per landed PR, by attribution class | Issue form with a "regressed in" field; a bot links to the PR |

The aim is to make the claims in B.7 measurable. Examples are agent-hours per PR, concurrent agents,
and the cost of a red main. It would also let the A.1 failure classes be split by attribution class
without guessing.

## B.9 Bottom line: what the evidence supports about speed versus quality

1. **VERIFIED.** The method produced very high throughput for an alpha:
   - about 0.89 M Rust lines and about 17 k `#[test]` attributes added in 6 weeks;
   - 3,285 landed PR numbers;
   - a release every 1.6 days (E03-012, E03-015).
2. **VERIFIED.** Throughput was front-loaded:
   - landed PRs per day fell from 192 (W41) to 10–79 (W44–W46);
   - median PR lifetime grew from 2.8 h to 68 h (E06-013);
   - human integration became the bottleneck, not agent output.
3. **INFERRED.** Quality held at the level of mechanical gates, not at the level of user-visible
   behaviour:
   - 77.5 % of commits touch tests, and crash, format, layering and corpus gates were enforced early;
   - yet over-claimed parity, inert settings (66/129) and vacuous tests (57 GPU checks) persisted until
     audits or users exposed them (F4–F6).
4. **VERIFIED (incidents) / INFERRED (classification).** The dominant red-main cause was semantic merge
   skew between individually-green PRs (11 of 21, E07-003). Repair was fast (median 68 min). Prevention stayed procedural: batches and a manual
   merge queue, never a mechanical merge queue (F1).
5. **INFERRED.** Parallelism amplified the failures that are combinational across PRs: merge skew,
   duplicates, gate-on-union failures and tracker conflicts. The project's corrective tooling is
   per-file (ratchets, lints) and did not address them (A.2, A.3).
6. **VERIFIED.** The fastest corrective loops ran from loud signals to mechanical gates:
   - crash reports → never-crash rule and sweep in under 24 h;
   - cancelled main runs fixed the same day;
   - release-day failure → nightly dry run the same day (A.3).
7. **VERIFIED.** Prose rules lagged reality. panic_hunt was unenforced for 13 days, and "fixes merged
   without" tests needed a backfill. The house rules answering RFC-0006's agent failure modes arrived
   on day 38 and remain unenforced (F4, F11, E02 §4).
8. **VERIFIED (sample) / INFERRED (generalisation).** Review is mostly bot review plus merge decisions
   by a few maintainers. Explicit human approval appears on a small minority of sampled PRs, and
   failing bot checks did not block merges (F12).
9. **VERIFIED.** The project measures its own failure modes where they are countable per file:
   - inert settings 66 → 8;
   - parity and corpus floors;
   - a shrink-only allowlist.
   It does not measure its own process costs: tokens, supervision, abandoned sessions (B.8).
10. **INFERRED.** Developers' effort and speed claims are of the right order where git can check them
    (PR counts, merge times). They are uncorroborated for agent counts and agent-hours, and
    contradicted for completion ("one-shot", "within a month") (B.7).
11. **INFERRED.** The provenance needed to judge the AI method itself is degrading. The attribution
    share fell from 50.1 % to 42.6 % after 11-06, mostly through contributor mix, and session ids
    cover 5.8 % of AI commits. A reader cannot tell from public data whether AI-attributed work fails
    more or less often than unattributed work (B.6, F13).

## Confidence and gaps
- **Weakest points.**
  - Review evidence rests on about 22 WebFetch-summarised PR pages (E05 + E06 + E09; errata #17) (F12).
  - Red-main TTF uses merge-to-merge times from E07's 21-incident table, not CI run times, so
    time-to-detect is folded in.
  - Fix-type shares depend on subject conventions that changed with landing style.
  - The attribution split (B.6) uses raw author names (no alias merging) and committer dates, so a
    few authors may be split or windowed differently than in E03.
- **Not checkable.**
  - Branch protection and required reviews.
  - PR open/closed state per head (only page totals via WebFetch).
  - Token cost, supervision time, prompts and abandoned sessions.
  - Whether the breaking PRs in E07 §2 were AI-attributed (not tabulated; this is the most useful next
    check for A.2).
- **What would change the conclusions.**
  - A merge-queue setting, or branch-protection data showing required approvals, would weaken F1/F12.
  - Per-PR attribution of breaking changes could move modes between "amplified" and "ordinary" in
    A.2.
  - Issue-tracker data on regressions per PR would replace the commit-subject rework proxies.
- **Evidence disagreements found.**
  - E07-013's "parity discrepancy" is two same-day commits (#182 and #186), not drift. Resolved in F5.
  - "(merge queue)" commit count: E07-003 says 9; `git log main --grep='(merge queue)'` gives 7 here.
    Resolved by errata #2: 7 on main, 9 across all refs.
  - The AI-share figures across E02/E03/E05/E07/E08 differ by denominator. Reconciled in B.6.
  - E03 reports `#[test]` 18,014 at the pin and E05-019 reports 18,111 (different counting). Noted in
    B.4.
  - E07 calls the 625/625 commit and the "decorative" fixes unattributed by omission. The clone shows
    all three carry `Claude Opus 4.8` trailers (see below).
