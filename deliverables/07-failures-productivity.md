# 07 — Failure and productivity analysis

Scope: how PhotoCraft (`storytold/photocraft`) failed, how fast failures turned into rules or gates, and
what its output and rework numbers can and cannot tell a reader who wants to copy the method. Upstream
pinned at `main` = `74330157cb` (2026-11-12). The history spans 44 UTC days, from 2026-09-30 to 2026-11-12.
ISO weeks run Monday to Sunday: W40 starts 2026-09-28, and W46 is partial (Mon to Thu).

Primary inputs are E07 (failures), E03 with `data/E03_*.csv` (quantities), E08 (developer statements),
E05 §1/§5/§7, E09 (case traces), E01 (genesis and parity), E02 (rules) and E06 (workflow). Every claim
carries an evidence ID and the underlying sha, path, PR or URL.

Labels: **VERIFIED** means seen in a primary source. **INFERRED** means reasoned from verified facts,
with the chain given. **PROPOSED** means our recommendation and not a PhotoCraft practice. A commit
without an AI trailer is "attribution unknown", not "human". Where a commit carries a trailer, this file
says "AI-attributed commit". It never says "the AI caused".

### Terms used below
- **Red main**: `main`'s CI is failing after a merge. "Fix main" commits repair it.
- **Semantic merge skew**: two PRs that are each green against their own base, but whose union fails
  (compile error, duplicate symbol, failing test). Without a merge queue, GitHub tests each PR alone.
- **Integration batch**: a maintainer branch that merges many community PRs, repairs them and lands as
  one merge commit. Examples are `davidmann4/integration-batch-7..20` (10-23 → 11-06) and
  `claude/integ-batch-1..11` (10-08/09, CI-only) (E07-002, E06-021/022).
- **Manual merge queue**: commits labelled "(merge queue)", in which main is merged into a PR and the
  gates are re-run before merging (e.g. fda05f7b02, 11-08).
- **Scorecard**: `docs/scorecard.md`, generated by `cargo xtask scorecard` and checked fresh in CI.
  Among other things it counts "Settings that do nothing" (E01-018, E07-014).
- **House rules**: the 15 org-wide rules copied into `AGENTS.md:1-20` from `storytold/craft-contrib`
  on 2026-11-06 (7d8648dfcb). Rule 15 is "No agent attribution" (E02-011).
- **panic_hunt**: a fuzz test that dispatches every command with hostile parameters
  (`crates/engine/tests/panic_hunt.rs`, added bf111b524e).
- **Mechanical** correction: a CI step, lint, test or compile-time check that fails without human
  judgement. **Advisory** correction: prose in AGENTS.md or docs, a label, or a review norm.

`merge_group` trigger in any workflow (E07-003, E05-052).

### F1 — Individually-green PRs collide on main (semantic merge skew)
- **Definition.** Two PRs pass CI on their own bases. Their union fails on main.
- **Incidents (VERIFIED, E07 §2).**
  - 6103da5278 (#798, 10-07): "Format red on main since #663 + #700".
  - 351149f0df (#6906, 10-17): "#5344 added the export_presets field … #5616 … lacked the new field,
    so main stopped compiling (E0063)". TTF 13 h 12 m.
  - 06650357d8 (#13128, 11-11): "#9781 and #10983 each defined TAG_JPEG_TABLES and TAG_PREDICTOR …
    merged minutes apart, so main stopped compiling (E0428)".
  - df055f3dcb (#5941, 10-15): "#5614 renamed the built-in profile … after #5208 hard-coded '(Photocraft)'".
- **Detection.** CI runs on main. Before 10-07 these were mostly cancelled (F3).
- **Correction.**
  - Integration batches from 10-18 (E07-002). Commits naming red main: W41 16, W42 4, W43–W45 0,
    W46 11 (E07-005). The W43–W45 zeros coincide with the batches. That is a correlation, not a
    demonstrated cause (INFERRED).
  - The manual "(merge queue)" practice from 11-08 (fda05f7b02). The grep `--grep='(merge queue)'` on
    main finds 7 commits on 11-08 to 11-11. E07-003 reports 9 with a different match, an unresolved
    small difference.
  - No GitHub merge queue (`merge_group` absent, E07-003). **Process, not mechanical.**
- **Agent link.** AGENTS.md §6, present since 10-01, already anticipates in-tree collisions between
  parallel agents: "If someone else's in-progress edit breaks the build, wait and retry; don't fix
  their files." (`74330157cb:AGENTS.md:174`, E02-003).

### F2 — Duplicate or conflicting work from parallel contributors and agents
- **Definition.** Two contributors or agents do the same work, or add the same row, constant or
  table. Detection then happens at merge or build time, or not at all.
- **Incidents (VERIFIED).**
  - 25f211500b (#834, 10-07): "Both PRs added Korean labels … ko.tsv listed each twice". The fixing
    commit is AI-attributed (Opus 5.5).
  - 29e4039c72 (#9009, 10-23): "Two PRs that landed together each added [people.ronibalthazar]".
  - 06650357d8: duplicate TIFF constants (E0428).
  - 252a47ef76 (10-11): "i18n(cs): drop rows #3039 and #3454 both added".
  - At PR level: closed-unmerged duplicate fixes #11854, #11846 and #11713 (E06-015, WebFetch). The
    Levels revert 70cb31610b was superseded by #3871.
- **Detection.** Compiler (E0428), catalog consistency tests (E07 §9 F2), maintainers, and the
  ticket-craft GitHub App, which labels issues `duplicate` (E06-033).
- **Correction.** House rules 2 "Check, then claim" and 6 "Look for a better pull request"
  (`AGENTS.md:7,11`, 11-06). Both are advisory. Issue epics with "Free to pick up / Being worked on"
  tables act as claim boards (#13458, E06-034).
- **Developer link (VERIFIED, P1).** RFC-0006 lists as observed agent failure modes "duplicate PRs,
  fixes for bugs already fixed on `main`, PRs left as drafts, or code that uses functions that don't
  exist" (https://github.com/storytold/craft-contrib/blob/main/rfcs/0006-coding-agents.md, via WebFetch,
  E08-028). The house rules are the stated answer.

### F3 — CI blind spots created by cost-cutting
- **Definition.** Saving runner time or slots removes coverage, so breakage surfaces later or in a
  different place.
- **Incidents (VERIFIED).**
  - "Between 09:56 and 20:34 UTC on 2026-10-07, 80 of 83 push runs on main were cancelled, and a
    formatting break from two PRs that were each green alone (#663 + #700) went unnoticed" (07174271d5,
    #800, Tanish Manku, AI-attributed commit, E07-004).
  - The same change made PRs Linux-only unless platform paths change or `full-ci` is set. Later
    Windows-only reds: ee3ebfa748 (#2042, "Windows CI red since #1882"), 184c226a76 (#4147) and
    79a33dae9c (#13199, the PR ran Linux only).
  - macOS removed from PR/main CI on 10-09 because "5 macOS slots in total" (bb3108cfd2). macOS is
    tested only by `release.yml` (`ci.yml:74-75`, E05-006).
  - Sonar is skipped on fork PRs (E05-029).
  - nextest's process isolation hid a race that `cargo test` on FreeBSD exposed (7091cb6b8c, E07-008).
- **Correction.**
  - Main runs never cancelled (`74330157cb:.github/workflows/ci.yml:66-68`), mechanical, the same day.
  - `full-ci` label, opt-in and advisory.
  - Day-rotating test sweeps cap cost while covering every case within N days (E05-021).
  - Cost trade-offs are documented inline in runner-minutes (E05-005).
  - The macOS gap remains.

### F4 — Tests that do not prove the fix (vacuous, skip-passing or missing)
- **Definition.** A test passes without exercising the behaviour, or a fix lands with no test that
  fails without it.
- **Incidents (VERIFIED).**
  - 2ff8f419cb (#7975, 11-06, FredApps, AI-attributed): "57 GPU checks … returned early and passed
    without comparing anything".
  - 1a86826ab7 (10-23): a test "passed without ever building a compositor pipeline".
  - 602344bae0 (#5549): "The mid-drag test asserted nothing … Verified by mutation".
  - a79db76e30: "the Alt+H/Alt+P cases checked nothing".
  - 72e11802d4 (#8690, 10-25): "Regression tests for eight fixes merged without one".
  - Sibling fix #1323 (437b25bea9) shipped with no test (E09-B).
  - 16 of 27 `Finding:` security fixes add no `#[test]` (E09-G-003).
- **Detection.** CI-environment audit, mutation spot checks ("mutation" in 24 commits), CodeRabbit
  (c441fd350c "CodeRabbit on #11369") and a backfill sweep.
- **Correction.**
  - The lavapipe wrapper fails on authored skips (`scripts/ci-gpu-lavapipe.py`, E05-024). Mechanical,
    Linux only; "this check does not certify Windows skip coverage" (`docs/development.md:116`).
  - "A zero-match run is BLOCKED, never PASSED" in the integration protocol (E05-022). Advisory.
  - House rules 4 and 5 (`AGENTS.md:9-10`). Advisory.
  - No mutation-testing gate exists.
- INFERRED link: the GPU skip and user issue #7 share one root, the `Rgba32Float` format being
  unsupported on a software or older adapter (issue #7 via WebFetch; 2ff8f419cb). The crash fix made
  the code skip gracefully, and the tests then skipped silently for weeks. The date the GPU tests began
  running on llvmpipe was not established.

  - Before/after failure rates in commit messages are a convention, not a rule. No AGENTS.md rule on

### F9 — Gate additions that themselves break main
- **Definition.** A newly tightened or newly added gate turns compliant work into red main or red
  unrelated PRs.
- **Incidents (VERIFIED).**
  - 604da9d06b (10-27) set `cognitive_complexity = "deny"` with threshold 30
    (`74330157cb:clippy.toml:8`). On 11-11, 47d3dcde33 (#13079) fixed "a cognitive complexity of 31
    (limit 30)", AI-attributed commit (`Fable 5.2`). 06650357d8 notes that two merged changes "pushed
    `prepare` past the clippy complexity limit". There is also e17091578e "Fix main: clippy after the
    11-11 merges".
  - The wasm 24 MiB size gate "failed unrelated PRs" once the build sat at the Cloudflare cap
    (df055f3dcb, E07-027).
  - The scorecard freshness gate went red on 192 vs 193 settings (3c44319455).
- **Detection.** CI on main.
- **Correction.** Fix-main PRs; the wasm build was split into gzip parts. INFERRED class mechanism
  (E07-005): a combinational limit, such as complexity of the merged function or total binary size,
  is not checked against the union. So skew (F1) turns into red main more often. No gate-rollout
  procedure (warn-then-deny, merge-queue check) was found.

- **Incidents (VERIFIED via WebFetch summaries).**

    current head" for each of 108 PRs (E05-022).
  - Branch-protection settings are not visible.
  - Developer rhetoric points the other way: "100% AI software factory and no human review" (HN
    50434834, scope ambiguous, E08-016).

### F13 — Loss of attribution and provenance
- **Definition.** Facts needed to audit who or what produced a change are lost or never recorded.
- **Incidents (VERIFIED).**
  - House rule 15 "A pull request does not say an agent wrote it" (`AGENTS.md:20`, 11-06). It
    contradicts the product's own About ▸ Models credits, which are built from trailers (E02-017).
  - Squash merges drop branch names (E03-010).
  - Merge-commit PRs drop the `(#issue) (#PR)` subject link: subjects carrying it fell from 327/1,064
    to 43/2,074 (E06-031).
  - Only 238 of 4,130 AI-attributed non-merge commits carry `Claude-Session:` (E03 §3).
  - Trailer model strings are unreliable. 0c2d4bfd1a estimates "Opus 5.5 effort" under a `Claude Opus
    4.8` trailer (E01-012). A `codex/` branch carries Claude trailers (#7809) or none (#9363,
    Codebuff on one commit, E09-E-003).
  - The handoff devlog is private (F14).
- **Correction.** None by the project. `Model-Effort:` trailers ("Opus 5.5 drove; … Sonnet 5.5 wrote
  at medium") appear on 25 commits, 11-07 → 11-11, voluntarily and without a documented rule
  (E03-005). They move in the opposite direction to rule 15.

### F14 — Private planning state invisible to contributors
- **Definition.** Agents and maintainers rely on state that outside contributors (and their agents)
  cannot read.
- **Incidents (VERIFIED).**
  - `plan/` ("research, parity plan, execution plan, estimates") and `log/` are gitignored from the
    first commit (`16941f7198:.gitignore`; `16941f7198:AGENTS.md:60-62`, E01-005).
  - The devlog is "how the next agent picks up" (`AGENTS.md:168`), so the main handoff medium is

  - `craftrules` standards were cited from AGENTS.md while the repo "returns 404 to everyone outside
    the organization" (f9b72468b4, issue #493, E02-013).

### F15 — Generated or tracker docs go stale; merge-conflict casualties
- **Definition.** Shared docs that every PR must update become stale, or are mangled by merges.

### F16 — Crash on hostile input or driver variance
- **Definition.** Panics on malformed input, unusual GPU capabilities or bad RPC parameters.
- **Incidents (VERIFIED, E07-009, E09-C).**

  - #16 / #17 (8a2f31c2c4, b6a95b6c8d): a panicking MCP command "wedges the headless session".

  - clippy deny and `forbid(unsafe)` (50a27e6c74);
  - an 11-PR crate-partitioned sweep in about 15 minutes (13:25–13:40);
  - `catch_unwind` guard (ab3ab92b4a);

  - The fastest loop in the history: user report to rule to sweep in under 24 h.

## A.2 Which modes are specific to or amplified by agent-driven, high-parallelism development

**Finding (INFERRED).** None of the 16 modes is unique to AI agents. Six are **amplified** by the
volume and parallelism the method produces: F1, F2, F9, F12, F13 and F15. Three are **agent-shaped**,
meaning they match failure patterns the developers themselves attribute to agents: F4, F5/F6 and F14.
The rest are ordinary engineering failures whose rate the evidence cannot tie to agents: F3, F7, F8,
F10, F11 and F16.

The amplifier is measurable without any AI attribution:
- up to 504 landed PRs were "in flight" on one day (10-13, E06-051);
- up to 49 landings happened in a 10-minute window (E06-013);
- 332 PRs landed on 10-09 (E03 §5);
- 582 author identities appeared in 44 days (E03-007).

## A.3 The corrective loop

**Finding.** Failures that a user or CI reported loudly turned into rules or gates within 0–2 days.

took weeks and got only process fixes, or got nothing. Every prose rule that later mattered was
converted into a check only after it had been shown not to hold (E05-071).
